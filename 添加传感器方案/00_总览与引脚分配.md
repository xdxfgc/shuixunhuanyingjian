## 二、通用套路：任何模块都是改 5 个地方

1. **新建一个 .cpp 文件**（复制原模块文件，改名 + 加后缀）
2. **改 `config.h`**：加引脚宏、加 `extern` 变量声明、加函数声明
3. **改主文件 `YF-S401_flow.ino`**：定义全局变量、`setup()` 里初始化、`loop()` 里轮询
4. **改 `web_server.cpp`**（可选）：加 JSON 字段、加 handler、注册路由、网页显示
5. **编译烧录 + 测试**

**最容易忘的两件事**：

- `config.h` 里写了 `extern`，就**必须在主文件里定义一次**（否则报 `undefined reference`）
- 复制文件后，里面**所有**变量名、函数名都要加后缀，否则报 `redefinition`

## 四、四条铁律（每次都要检查）

1. **`analogRead(引脚)` 会抢走那个脚的中断和数字功能。** 任何做中断/脉冲测量的脚（流量计）绝不能出现在 ADC 自检里——D34 已经踩过一次这个坑。
2. **模拟量传感器（压力、模拟光照）必须用 ADC1**：D32、D33、D34、D35、D36、D37、D38、D39。**不能用 ADC2**（D0/D2/D4/D12/D13/D14/D15/D25/D26/D27），WiFi 一开就读不准。
3. **OneWire（DS18B20）、I2C、继电器不能用 D34~D39**（输入专用脚，不能输出、不能拉低总线）。但做**纯输入**的脉冲测量可以。
4. **每个 5V 供电的传感器，信号线都要分压**（10kΩ 串 + 20kΩ 到 GND），并且**所有电源的 GND 必须和 ESP32 共地**。

## 五、引脚选择的判断流程

```
这个传感器输出什么？
├─ 模拟电压（0~3.3V / 0~5V）   → 必须 ADC1（D32~D39）；接 5V 输出要分压
├─ 脉冲 / 开关量（流量计、霍尔）→ 任意脚；做中断优先选双向脚 D4/D5/D13/D14/D16/D17/D19
├─ 单总线（DS18B20）           → 必须双向脚（不能 D34~D39），要 4.7kΩ 上拉
├─ I2C（BH1750 等）            → 优先共用已有总线 D21/D22，靠地址区分
└─ 执行器（继电器）             → 任意输出脚，避开启动脚 D0/D2/D5/D12/D15
```

### 关于 strapping（启动）脚：D0 / D2 / D5 / D12 / D15

这 5 个脚在上电瞬间的电平会影响 ESP32 的启动，原则是"能用，但要保证上电时的电平正确"：

| 引脚 | 上电要求 | 实际影响 |
|------|---------|---------|
| D0 | 高电平才进正常启动 | 被拉低会进烧录模式，**建议避开** |
| D2 | 低电平 | 常与板载 LED 冲突，**建议避开** |
| **D5** | 高电平（内部默认上拉） | 只影响 SDIO 从机时序，**普通开发板正常使用没问题** |
| D12 | 低电平 | 拉高会导致 Flash 电压不对，**必须避开** |
| D15 | 高电平 | 被拉低会进调试输出模式，**建议避开** |

> 本方案里 **水温 3 用 D5**：DS18B20 的数据线有 4.7kΩ 上拉到 3.3V，**上电时天然就是高电平**，正好满足 D5 的要求，可以放心用。
> 想完全避开 strapping 脚的话，把水温 3 改到 **D17**（注意：带 PSRAM 的 WROVER 板子 D16/D17 被占用，不能用）。
